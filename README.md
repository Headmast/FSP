# Трудяжки · ФСП — обратный найм и подтверждение компетенций

Проект для «Лидеров цифровой трансформации 2026»: кандидат подтверждает навыки тестом, а работодатель находит подходящего специалиста и отправляет адресное предложение с зарплатной вилкой. Контакты кандидата открываются работодателю после принятия приглашения.

Этот README — оглавление проекта: документация, презентация, демо, исходники прототипа, требования, исследования и результаты проверок. Материалы собраны по состоянию на **11 октября 2026 года**.

## О проекте

**Для кандидата:** профиль и резюме, тестирование, подтверждённая категория, демонстрационные достижения ФСП, свидетельство результата, приглашения работодателей и решение о раскрытии контактов.

**Для работодателя:** профиль компании, описание потребности, поиск и объяснимый подбор, приглашение с условиями и зарплатой, отслеживание решения и контакты после согласия.

Сквозной сценарий: **профиль → тест → категория → подбор → приглашение → согласие → контакты**. В техническом демо выбраны специализация **iOS / Swift** и уровни **Junior / Middle**. Презентация описывает более широкую концепцию, включая общую матрицу компетенций и направления развития.

Стек: Python 3.13, Django 5.2 LTS, серверные HTML-шаблоны, JavaScript, SQLite и Gunicorn. Базовый прототип работает отдельно без backend и внешних библиотек. Зависимости закреплены в [pyproject.toml](pyproject.toml) и [uv.lock](uv.lock).

### Что показать на демонстрации

1. Кандидат регистрируется, проходит демонстрационное подтверждение email, даёт согласия и заполняет профиль.
2. Выбирает заявленный уровень, проходит тест и получает подтверждённую категорию.
3. Работодатель заполняет компанию и потребность, открывает подбор и объяснение соответствия.
4. Отправляет приглашение с описанием, зарплатной вилкой и способом связи.
5. Кандидат принимает приглашение; его контакты открываются этому работодателю.
6. Отдельно показать отказ: он не открывает контакты. Помощник обозначен как мок; применение черновика и отправка приглашения требуют явного действия пользователя.

В базовом прототипе роли переключаются внутри одного интерфейса — это имитация доступа. Порядок действий и ответы демонстрационного теста: [инструкция прототипа](prototype/README.md).

## Статус и ограничения

Технический демонстрационный сценарий опубликован. [Checkpoint 80091ff](doc/delivery/assistant-checkpoint.md) фиксирует выпуск черновиков и помощника, 90 тестов и 15 шагов HTTPS-проверки. Это исторические результаты того выпуска; текущий SHA сервера виден на странице демо.

В расширенном плане на момент сборки оглавления закрыты **13 из 27 задач**, **14 открыты**. Актуальные статусы: [backlog](doc/plan/backlog.md), [прогресс](doc/delivery/implementation-progress.md), [условия завершения](doc/plan/remaining-work.md).

- Помощник работает на явно обозначенном моковом провайдере; живой AI не подключён.
- Email демонстрационный и не проверяет владение настоящим ящиком.
- FSP ID и достижения демонстрационные; настоящая интеграция не подтверждена.
- Валидация использует синтетические профили и не доказывает качество на реальных кандидатах.
- Полный OpenAPI, комплект сдачи с репетицией, постоянный адрес backend, живые интеграции и пилот остаются в плане. Сбор материалов в README сама по себе не закрывает DEL-001.
- Презентация отражает концепцию и развитие, которые шире реализованного демо.

В комплект включены шесть видео: пять иллюстраций концепции и запись мокового прототипа. [Просмотр на LLM Love](https://llmlove.ru/dreamwork/video/index.html).

## Локальный запуск

### Базовый прототип

Из корня репозитория:

```sh
python3 -m http.server 8010 --bind 127.0.0.1 --directory prototype
```

Откройте [http://127.0.0.1:8010](http://127.0.0.1:8010). Подробный сценарий: [prototype/README.md](prototype/README.md).

### Django MVP

Нужны Git, Python 3.13 и uv. В основном checkout:

```sh
uv sync --locked
uv run python app/manage.py migrate
uv run python app/manage.py collectstatic --noinput
uv run python app/manage.py seed_demo
uv run python scripts/run_app.py
```

Откройте [http://127.0.0.1:8011](http://127.0.0.1:8011). В worktree используется порт его конфигурации.

После `seed_demo`: кандидат `fixture-junior-01@demo.invalid`, работодатель `fixture-company-alpha@demo.invalid`. Публичный демо-пароль: `Fsp-demo-2026!`. Используйте вымышленные данные. Остальные аккаунты, регистрация, окружение и проверки: [инструкция запуска](doc/development/local-run.md), [.env.example](.env.example).

### Сайт команды

Для просмотра откройте [index.html](index.html) в браузере. Сборка и библиотеки не нужны; [style.css](style.css) содержит общие адаптивные стили.

GitHub Pages можно настроить через **Settings → Pages → Deploy from a branch → main → root**. На 11.10.2026 адрес `https://headmast.github.io/FSP/` ответил HTTP 404 и не используется как действующая ссылка демо. [_config.yml](_config.yml) исключает документацию, инструменты, приложение и прототип из стандартной Jekyll-сборки; для другого режима публикации нужен отдельный артефакт сайта.

[Рабочая стратегия](strategy-71c4.html) помечена `noindex, nofollow`; [robots.txt](robots.txt) разрешает обход для чтения метатегов. Это настройки индексации, а не ограничение доступа.

## Работа с проектом

Прочитайте [AGENTS.md](AGENTS.md), [цель](doc/goal.md), [backlog](doc/plan/backlog.md) и [инструкцию worktree](doc/development/worktrees.md). Каждый чат работает в своей ветке и checkout; успешный этап заканчивается проверками, документацией и отдельным коммитом.

```sh
python3 scripts/worktree.py create assessment --base main --port 8021
python3 scripts/worktree.py list
python3 scripts/check_docs.py
python3 -m unittest discover -s scripts/tests -v
```

При добавлении материала сохраните его в соответствующем разделе `doc/`, добавьте относительную ссылку и описание в оглавление, укажите дату и статус. Не заменяйте доказательства готовности описанием концепции. Секреты, реальные данные пользователей, базы и runtime-логи в Git не добавляются.
