# Воспроизводимые HTTP примеры

Эти примеры относятся к [контрактам](contracts.md) и [общему OpenAPI](openapi.json): браузерные формы и интегрированный [JSON API MCP/CLI](mcp-cli.md). Не использовать примеры записи против чужих аккаунтов или production: проверка ниже создаёт собственный временный стенд.

## Полный прогон без живых доступов

В собственном checkout с Python 3.13:

```bash
uv sync --locked
uv run python scripts/build_client_release.py
uv run python scripts/build_http_spec.py --check
uv run python -m openapi_spec_validator doc/api/openapi.json --schema 3.1
uv run python scripts/check_http_contracts.py --output .runtime/qa/http-contracts.json
```

Последняя команда переопределяет путь БД до загрузки Django и создаёт временную SQLite вне checkout. Окружение родителя с DATABASE_PATH не может направить запись в рабочую/серверную БД. Используется настоящий Django Client с enforce_csrf_checks=True, сессиями и cookie, формы сериализуются как URLencoded. Файлы PDF действительно генерируются. Архивы CLI перед этим собираются из текущих исходников в собственную .runtime/downloads; проверка читает их и сверяет manifest/hash/размер. После завершения временная БД удаляется. Это HTTP внутри Django, а не проверка TLS/прокси или внешний браузер.

Сценарий задаёт ожидаемые статусы независимо от OpenAPI, а затем сравнивает фактический ответ со схемой. Он выполняет:

- Регистрацию с explicit processing consent → 302 confirm; неверный токен → 400, верный → 302, повтор → 404; обычный вход, безопасный next, выход и CSRF-отказ.
- Сохранение профиля с опытом, повторяемыми roles/soft_skills и отдельной публикацией → 302. POST JSON не сохраняет форму. Company/Need проверяют свои поля и зарплатную вилку.
- FSP connect DEMO-001/EMPTY/DOWN → 302, соответствующие JSON состояния и даты; unlink → not_connected. Это синтетические достижения.
- Start → активная попытка, повтор → тот же URL, answer/finish → 302; неизвестный вопрос и просрочка не сохраняют новые ответы, повтор завершения не меняет результат. Отдельно проверяется безопасное свидетельство.
- Генерацию и просмотр Draft → 200; невалидное применение → 400, конфликт → 409, истёкший срок → 410; явное сохранение → 302, повтор не создаёт вторую Need.
- Matching/invitation/conversation для допустимого контекста → 200; отправку → 302 с неизменяемым snapshot; принятие/отказ и повтор; контакты только у принявшей компании. Частичный выбор GET показывает форму; полный чужой контекст → 404.
- Провайдерный отказ → 503, лимит → 429, активный экзамен → 409. Эти отказы вводит тестовый стенд, а не внешний AI. Health при отказе БД → 503.
- Все разрешённые операции, GET/HEAD, OPTIONS входа/выхода, чужие объекты, роль/email/consent и PUT → 405 с точным Allow. HEAD не содержит тело; JSON имеет проверенные поля, PDF — MIME/attachment и %PDF signature.
- Новый кабинет владельца, period/hr/need фильтры и HR назначение; создание/revoke собственного подключения, отказ MCP контактов и private API. Все token GET endpoints проверены реальными синтетическими Bearer token, DTO, JSON ошибками, заголовками, rate limit и revoke. Публичные wheel/tar.gz/manifest проходят MIME/signature/hash и HEAD.

Временный стенд знает правильные ответы только для своей фикстуры. Они используются для создания завершённого свидетельства и не входят в отчёт, provider context или примеры ответа пользователя. Это не независимая валидация тестового банка: она находится в QA-001.

Отчёт содержит статус, команды/срез и source hashes, операционное покрытие, ожидаемые/фактические статусы, media type и безопасный redirect. Не сохраняются password/token, cookie, приватные тела ответов или ключи теста. Source hashes связывают прогон с незакоммиченным кодом; после коммита результат следует повторить с точным SHA.

Три контрпроверки обязаны отвергнуть намеренно повреждённую спецификацию: удалённый маршрут, отсутствующий успешный статус и неверный JSON const. Отрицательная контрпроверка PASS означает «повреждение поймано», а не успешную работу повреждённого интерфейса.

## Чтение работающего локального приложения

После запуска по [инструкции](../development/local-run.md), на своём порту:

```bash
curl --fail http://127.0.0.1:8041/health/
curl --fail http://127.0.0.1:8041/version/
curl --head http://127.0.0.1:8041/version/
```

Ожидаемо: health HTTP200 `{"status":"ok"}`; version HTTP200 с commit SHA и assistant_mode=mock; HEAD — такие же заголовки без тела. При отказе требуемой таблицы health возвращает HTTP503 `{"status":"unavailable"}`. Это три публичных запросa; PDF/FSP/профиль требуют browser session.

Для реального URL прочитайте публичный `https://llmlove.ru/dreamwork/fsp-demo-status.json`, поле url. Страница fsp-demo.html — входной портал, а не сервер API. Version фиксирует код приложения, не обязательно последний документационный commit Git.

## Форма запроса и ответ

Пример URLencoded профиля, после входа в свою сессию:

```text
desired_grade=Junior&name=Анна&skills=Swift%2C+Core+Data&roles=developer&roles=reviewer&published=true&csrfmiddlewaretoken=<TOKEN_OF_THIS_SESSION>
```

Токен нужен с cookie csrftoken этой же сессии; вместо поля допустим X-CSRFToken. Ожидаемый успешный ответ — HTTP302 `Location: /profile/`. Невалидные поля — HTTP200 с ошибками формы; отсутствующий CSRF — HTTP403. roles[] — другое имя, оно не заменяет roles. Предварительное GET формы устанавливает нужные cookie; после login токен следует получить заново.

Пример нового предложения (ID своей Need, видимого кандидата и завершённого свидетельства заменить реальными локальными ID):

```text
need=1&candidate=2&accepted_attempts=3&discussion=Обсудим+задачи
```

С cookie/header CSRF: HTTP302 `/invitations/`; повтор оставляет первый snapshot. Некорректное/чужое need — 404; отсутствие company email — 302 `/company/`; неподходящее свидетельство — 302 к карточке с message. Нельзя считать любой 302 отправленным предложением. Для ручного подтверждения используйте штатную кнопку браузера.

В OpenAPI сохранены формы остальных POST и JSON примеры. Значения-заглушки не являются рабочими токенами/аккаунтами. Для полного воспроизводимого набора с настоящими локальными ID и проверкой последствий используйте checker, описанный выше.
