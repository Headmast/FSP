# MCP и CLI: план реализации

Поручение: обе роли, V1 чтение и V2 черновики с подтверждением браузерной сессией.
База: 80091ff, ветка mvp/mcp-cli, порт 8043. Владелец всех MCLI задач: текущий чат.
Область: общий доступ, accounts/integrations, app/api, clients/python, документы и проверки.
DOC-003 не закрывается автоматически: OpenAPI нового API дополняет существующий HTML контракт.

V1: Django /api/v1, scopes candidate.read/employer.read, отдельный CLI contacts.read;
MCP stdio с отдельным токеном, без контактов/свободного текста/вопросов и ответов теста.
Чтение не создаёт компанию, не отмечает приглашения просмотренными и не завершает тест.
Ранжирование и правила ранее принятого предложения сохраняются.
CLI: Python 3.13, argparse, HTTPX, keyring, официальный MCP SDK, macOS/Linux.
Секреты только в системном хранилище. JSON/PDF и понятные коды выхода.

V2: immutable черновик на 24 часа, owner/kind/target/payload/fingerprint/status.
Токен может prepare/list/get/cancel при явно выданном draft scope, но не apply.
Веб подтверждение с CSRF, повторной проверкой прав/согласия/версии данных.
Профиль, публикация, компания, потребности, отправка/принятие/отказ приглашения.
Тестирование и FSP ID остаются в веб. Повторное применение идемпотентно.

Приёмка: изоляция двух компаний; отказ/чужое принятие не раскрывают контакты;
вопросы/ключи/произвольные snapshots не выходят в API; revoke/expiry/role/consent;
MCP безопасен и при вредоносных данных; GET не меняет бизнес-модели;
поиск совпадает с web; CLI wheel без Django; MCP официальный SDK; stale/expiry/cancel/
concurrent/replay черновиков. Evidence новых проверок отдельно от исторических gates.

Демо: только синтетические данные. API URL задаётся явно; credentials не переносятся
при смене origin. Настоящий пилот, Windows, remote MCP/OAuth и ATS вне этапа.
Linux и опубликованный сервер отмечаются PASS только после фактической проверки.
