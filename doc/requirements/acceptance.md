# Требования и критерии приёмки

Главный сценарий — обратный найм: работодатель инициирует предложение, кандидат решает, раскрывать ли контакты. Категория подтверждается общим тестом направления, а не тестом конкретной вакансии.

| Требование | Задача | Проверка | Критерий |
|---|---|---|---|
| R01 Полный прототип на моках | MVP-001 | P0 | HTTPS сценарий, сброс, явные моки, коммит и push |
| R02 Две роли и подтверждение demo email | MVP-002 | AUTH-01–03, G2 | Сессии и токены ограничены владельцем |
| R03 Профиль, публикация, PDF | MVP-002 | PROFILE-01–03 | Чужое редактирование запрещено, кириллица читается |
| R04 Категория из теста | MVP-003 | ASSESS-01–07, G3 | Серверный результат и правила порогов |
| R05 История ФСП необязательна | MVP-003 | FSP-01 | Без истории путь работает, категория не меняется |
| R06 Поиск подтверждённых кандидатов | MVP-004 | MATCH-01–03 | Фильтры соблюдены, рейтинг воспроизводим |
| R07 Предложение с зарплатой | MVP-004 | HIRE-01–03 | Валидная вилка, снимок условий, нет дубликатов |
| R08 Контакты только после согласия | MVP-004 | ACCESS-01–03 | Доступ только отправителю принятого предложения |
| R09 Помощник на моках без ключа | MVP-004 | AI-01–03, G5 | Явная метка мока, отсутствие внешних запросов, ошибка и лимит |
| R10 Проверяемый выпуск | MVP-005 | LOAD-01, RELEASE-01–03, G6 | Перезапуск, версия и отчёт |
| R11 Параллельные worktrees | DEV-001 | DEV-01 | Изоляция checkout, runtime и портов |

Каждому результату проверки добавлять SHA, дату и evidence. Не считать синтетические результаты подтверждением валидности оценки реальных разработчиков. Технические правила закреплены в [архитектуре](../architecture/system.md).

## Дополнение по аудиту полноты

R01–R11 — прежняя карта технического демо, не весь состав исходного плана/ТЗ. Частичное выполнение R03/R05/R06/R07/R09 раскрыто ниже. Новые проверки ещё NOT_RUN; требования не считаются выполненными из-за старых G1–G6.

| Требование | Задача | Проверка | Незакрытая приёмка |
|---|---|---|---|
| R12 Полный профиль и специализация | MVP-006 | PROFILE-04–07 | Опыт/роли/стаж/софт-скиллы/описание, PDF и приватность |
| R13 Компания и способ связи | MVP-007 | COMPANY-01–03, HIRE-04 | Описание/деятельность, собственное редактирование, обязательный канал в снимке |
| R14 Обработка и публикация с согласиями | MVP-008 | CONSENT-01–04 | Явные согласия, дата/версия, отказ и снятие видимости |
| R15 Демо FSP ID и достижения | MVP-009 | FSP-02–06 | Связь/отвязка, записи и источник, контракт будущего адаптера |
| R16 Свидетельство и зачёт в приглашении | MVP-010 | PROOF-01–04, HIRE-05–07 | Дата/метод/области/критерии, адресный зачёт и вопросы |
| R17 Предметные объяснения подбора | MVP-011, FIX-002 | MATCH-04–06, SKILL-01–03 | Совпадения/пробелы/неизвестное и единые навыки |
| R18 Варианты для новых кандидатов | MVP-012 | ASSESS-08–11 | Распределение A/B, снимок и покрытие |
| R19 Независимая валидация уровня | QA-001 | VALID-01–03 | Test–retest, разделяющая сила и сопоставимость |
| R20 Применение черновиков | MVP-013 | AI-04–06 | Профиль сохраняет черновик, новая потребность создаётся с помощником |
| R21 Помощь на остальных этапах | AI-001 | AI-07–08 | Разрешённые моки подбора/приглашения/разговора; прямое общее пожелание |
| R22 API и комплект сдачи | DOC-003, DEL-001 | API-01–03, DELIVERY-01–04 | Фактические контракты, OpenAPI, согласованные PDF/слайды/демо |
| R23 Устойчивые ID и актуальный health | FIX-001, OPS-002 | ID-01–03, OPS-01–03 | Нет 500 на проверенных ID; отказ БД не даёт зелёный статус |
| R24 Восстановление после reboot | OPS-003 | OPS-04 | Реальная проверка пока NOT_RUN; эксплуатационное усиление |

Источник и подробная область каждого пункта — [оставшиеся работы](../plan/remaining-work.md), [исходный план](../sources/original-mvp-plan.md) и [свод ТЗ](../sources/requirements-map.md). R16/R21 отражают план/пожелания команды, а не новые обязательные нормы ФСП. Реальные интеграции INT и гипотезы PROD/QA-002/FUT выделены отдельно.
