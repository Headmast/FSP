# Трудяжки · ФСП — текущий демонстрационный MVP

**Кратко:** кандидат подтверждает категорию iOS/Swift, работодатель предлагает конкретные условия и получает контакты после принятия своего приглашения. Свидетельство теста переносится между предложениями; helper, FSP и мессенджеры работают на явно обозначенных моках.

Код материала: `34942b532e0ad1643db37e957ccfec30f6d77a6b`. Контракт и исправления V2 проверены на `3013085`; приложение совпадает с кодом этого среза. Это материал реализованного демо; [концептуальная презентация](../presentation/trudyazhki-fsp.md) сохраняет идеи развития отдельно.

## Пользовательский путь

1. Соискатель регистрирует demo email и даёт processing-v1. Одноразовое подтверждение доступно только этому браузеру 30 минут.
2. Заполняет имя/город, навыки, стаж/роли/софт-скиллы и частный опыт/описание. Отдельно разрешает публикацию. Собственный PDF содержит контакты.
3. Выбирает Junior/Middle и проходит iOS тест: 8 вопросов, 4 области, 15 минут. Результат вычисляет сервер, вариант и ответы фиксируются; подтверждение требует 6/8 и хотя бы 1/2 в каждой области.
4. Компания указывает задачи, положительную вилку в рублях до налогов за месяц, формат и следующий шаг. Поиск включает опубликованные профили подтверждённой категории и объясняет совпадения/пробелы.
5. Работодатель изучает свидетельство и явно выбирает, какие результаты зачесть в предложении. Контакты и частный текст закрыты до принятия; условия сохраняются снимком.
6. Кандидат принимает или отклоняет. Принятие открывает контакты только компании-отправителю в HTML/PDF/API/CLI; повтор не меняет решение. У другой компании доступа нет.

## Правила оценки и подбора

- Категория: iOS/Swift + Junior/Middle. Стаж/заявленные навыки/роли — самоописание, FSP — отдельный сигнал.
- В банке 32 задания: по 2 варианта × 8 на каждый уровень. Срок 15 минут, одна активная попытка. Варианты распределяются и ротируются, порядок ответов перемешивается.
- Провал повышения не понижает категорию. Повтор того же уровня — 7 дней; успешная смена подтверждённого — 30 дней. После первой неудачи Middle доступен Junior.
- Ранг внутри категории: `85 × доля правильных + 10 × доля заявленных совпадений + FSP(0..5)`. Без желаемых навыков вклад совпадений 0 у всех; равенство — тест, затем ID.
- FSP: участие 3, приз ещё 2, события не суммируются. Нет истории — обычный путь, без автоматического исключения или повышения грейда.

## Данные и архитектура

Django 5.2 LTS с серверными шаблонами; Python 3.13; SQLite WAL/IMMEDIATE, короткие транзакции; Gunicorn 1 worker × 4 threads; WhiteNoise; ReportLab с кириллическим шрифтом. Версии фиксирует uv.lock. Текущий запуск не требует React/FastAPI/PostgreSQL/Compose.

Веб-кабинет и token `/api/v1/` используют общие проверки доступа. Клиент `clients/python` — самостоятельный пакет CLI/MCP; локальный MCP stdio, секреты CLI в системном keyring. База, ключи, журналы и runtime исключены из Git.

| Модуль | Основные данные | Ответственность |
| --- | --- | --- |
| accounts | User, ConsentEvent, DemoConfirmation, ApiToken | Роль, обработка, demo email, session/Bearer, отзыв токена |
| profiles | Profile, Experience, FspLink, Achievement | Публикация/частный текст/PDF, демо-источник ФСП |
| assessments | Attempt, LessonProgress, PracticeSession | Неизменяемый снимок экзамена, критерии; отдельная практика |
| hiring | Company, Recruiter, Need, Invitation | Условия/ранг/предложение, snapshot, адресный грант, HR атрибуция |
| assistant | Draft, Usage | Разрешённые моки, лимит и применяемый человеком черновик |
| api | ActionDraft | 24-часовые V2 черновики и веб-подтверждение |

## Дополнительные интерфейсы

**Обучение:** iOS, Android, Flutter, Аврора; 32 урока/128 вопросов, отдельный прогресс, пауза, разбор и повтор ошибок. Учебный балл не повышает категорию. Подсказки блокируются во время активного экзамена (423, dashboard показывает путь возврата).

**MCP/CLI:** V1 читает собственные разрешённые сведения; GET не меняет бизнес-состояние. MCP не получает контакты/частный свободный текст/PDF. V2 готовит девять видов immutable черновиков: профиль/публикация, компания/потребность, отправка/решение приглашения. Apply только в браузере с session/CSRF, acknowledgement и publication consent при публикации; stale 409, expiry 410. При prepare бизнес-объект не меняется. Свой HR задаётся nullable ID; чужой HR отвергается. Полная клиентская V2 приёмка MCLI-013 остаётся открытой.

**Кабинет владельца:** фильтры, воронка, конверсия/время ответа/давние ожидания и атрибуция HR. HR — ответственные лица в общем кабинете компании, не отдельные пользовательские аккаунты. Принятое предложение не считается трудоустройством.

**Доступность:** упрощённый режим, масштаб/контраст/интервалы, клавиатура и локальная озвучка. Автоматические проверки есть; ручной VoiceOver/NVDA не закрыт.

**Боты и мобильность:** Telegram/MAX информационный бот — локальный мок без внешних мессенджеров. Веб адаптивен; Android/Flutter WebView проекты и APK существуют рядом с репозиторием, перенос исходников в Git и новые сборки ещё открыты.

## Фактическое QA и границы

DOC-003: **148 тестов приложения, 23 теста инструментов, 577 HTTP случаев, все 69 маршрутов/111 операций, 57 примеров и 4 контрпроверки — PASS**. PDF/архивы проверяются как файлы; wheel совпадает с текущими исходниками клиента. Включены права двух компаний, CSRF, ID/UUID, повтор/срок/stale и учебные блокировки.

QA-001: anchors и holdout прошли заранее заданные synthetic критерии; пограничные профили нестабильны. Это не точность оценки реальных специалистов и не подтверждение экономии времени найма. Протокол/ошибки доступны в doc/qa/validation-results.md.

Полный объём исходных 27 задач остаётся активным. Пилот, живые SMTP/FSP/Yandex, постоянный backend/reboot, этапы после приглашения, отзыв старых грантов/удаление, жалобы и другие функции не закрыты. Снятие публикации сейчас сохраняет ранее принятый адресный грант.

## Воспроизводимый запуск

```sh
uv sync --locked
uv run python app/manage.py migrate
uv run python app/manage.py collectstatic --noinput
uv run python app/manage.py seed_demo
uv run python app/manage.py seed_owner_dashboard
uv run python scripts/build_client_release.py
uv run python scripts/run_app.py
```

Для отдельного checkout: `python3 scripts/worktree.py create demo --base <SHA> --port 8071`, затем работать в возвращённом каталоге. Он имеет свои .env.worktree/.venv/.runtime/БД/порт. Входы фикстур: fixture-junior-01@demo.invalid, fixture-company-alpha@demo.invalid, fixture-owner@demo.invalid; публичный синтетический пароль Fsp-demo-2026!. Не использовать его для реальных пользователей.

Проверки: `uv run python app/manage.py test accounts profiles assessments hiring assistant api`; `python3 -m unittest discover -s scripts/tests`; `uv run python scripts/build_http_spec.py --check`; `uv run python scripts/check_http_contracts.py`; `python3 scripts/check_docs.py`. HTTP checker создаёт свою временную БД и не использует production.

## Публикация, версия и восстановление

Постоянный вход: https://llmlove.ru/dreamwork/fsp-demo.html. Статус: https://llmlove.ru/dreamwork/fsp-demo-status.json. Прямой адрес туннеля меняется, после смены пользователь входит заново. Перед демонстрацией сверить /health и /version с выбранным серверным SHA; локальная подготовка комплекта не является серверным evidence.

Выпуск: releases/<SHA>, current symlink, shared конфигурация/БД/backup. Deployment делает backup до миграций; watchdog по cron проверяет version + health + HTML и публикует новый адрес. Не вращает исправный туннель при отказе БД. Откат совместимого кода — deploy_mvp.py с прежним SHA; несовместимый schema rollback требует отдельного плана восстановления и учета новых записей. Реальный reboot и полный эксплуатационный gate остаются открытыми.
