## 6. MCP, CLI и проверяемые изменения



Персональные токены и scopes
MCP без контактов и частных текстов

V2 готовит неизменяемый черновик
Применяет человек в веб-кабинете

Срок 24 часа; конфликт проверяется

Выступление:

Token API V1 читает доступные сведения, а GET не меняет бизнес-объекты. CLI использует системный keyring; MCP работает через локальный stdio. V2 охватывает профиль, публикацию, компанию, потребность и приглашения. Только browser session, CSRF и явное подтверждение позволяют apply. Истёкшие и устаревшие черновики отвергаются, повтор применённого безопасен. Полная клиентская приёмка MCLI-013 ещё открыта. Source: doc/api/contracts.md, doc/plan/mcp-cli.md.

Выступление:

Контрактный набор покрывает все текущие маршруты и методы, типы и примеры; четыре контрпроверки отвергают ложную спецификацию. Это не точность на людях и не измеренная экономия времени найма. Живые интеграции, reboot, полный эксплуатационный gate и дальнейший продуктовый маршрут остаются открытыми. Прямой адрес приложения временный; cron обновляет стабильную страницу входа. Source: doc/qa/DOC-003-complete.json, validation-results.md, doc/plan/remaining-work.md.
