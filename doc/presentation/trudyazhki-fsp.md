Презентация решения для ЛЦТ 2026. Версия с уточнениями по замечаниям Джа от 11 октября 2026 года. 18 слайдов, выступление примерно на 9–10 минут.

Статус проекта: концепция и план MVP. Презентация описывает выбранное устройство продукта. Файлы проекта не подтверждают готовую платформу, живую интеграцию ФСП или результаты пилота.

## Слайд 4. Проблема и выбор решения

### Текст на слайде

#### Разные представления об уровне

Название «Middle» само по себе не объясняет, какие задачи решает кандидат. Резюме и результаты соревнований требуют проверки.

#### Общая шкала для двух сторон

ТЗ ФСП и ответы постановщиков задают сценарий найма. Матрица связывает тест кандидата с требованиями вакансии.

#### Что предстоит проверить

Критерии уровней должны быть понятны экспертам. Тесты должны проверять эти критерии, а подбор показывать пробелы.

### Выступление

Мы выбрали задачу подтверждения навыков для найма участников ФСП. У работодателей разные представления о грейдах, поэтому одного названия уровня недостаточно. Из ТЗ и ответов постановщиков следует необходимость подтверждать категорию кандидата и подбирать его под потребность компании. Наше проектное решение — сделать критерии навыков открытыми и использовать их с обеих сторон. Достижения ФСП сохраняем отдельным источником. Проверим матрицу с экспертами, качество тестов и понятность подбора.

## Слайд 7. Матрица компетенций

### Текст на слайде

#### Открытые критерии

Для каждого навыка описываем проверяемое умение и критерии уровня. Компания выбирает требования из этой матрицы.

#### Пример: Backend

Junior: SQL-запросы с JOIN, обработка ошибок API.
Middle: оптимизация запросов, проектирование API.

#### Подтверждение тестом

Кандидат выбирает грейд. Рубрика теста проверяет его и показывает результаты по навыкам. Повышение требует нового теста.

### Подпись на слайде

Пример критериев. Полную матрицу и пороги предстоит проверить с экспертами.

### Выступление

Матрица раскрывает, что именно означает уровень. Пример для Backend иллюстративный: работа с SQL и API должна иметь наблюдаемые критерии. Для более высокого уровня проверяем более сложные умения, например оптимизацию запросов. Полную матрицу и пороги утверждаем после экспертной проверки. Кандидат выбирает уровень, а тест проверяет его по заранее заданной рубрике. Работодатель выбирает требования по этой же матрице. Спортивное достижение не присваивает профессиональный грейд. Неудачная попытка оставляет статус «не подтверждён» и возможность проверить уровень ниже. Интервал смены подтверждённого грейда в 90 дней остаётся предложением команды.

## Слайд 8. Как тест проверяет навыки

### Текст на слайде

#### Навык и критерий

Каждая задача проверяет конкретное умение из матрицы. Например, составить SQL-запрос с JOIN.

#### Проверенный банк задач

Эксперты отбирают варианты с одинаковыми критериями и близкой сложностью. История выдач исключает повтор набора.

#### Понятный результат

Профиль показывает подтверждённые навыки и пробелы. Для каждой попытки сохраняем ответы и версию критериев.

#### Обновление банка

Команда проверяет спорные оценки и убирает задания с утечками. Сопоставимость вариантов проверяем отдельно.

### Выступление

Тест строится из матрицы: сначала задаём проверяемое умение, затем подбираем задания и критерии оценки. Например, умение составить JOIN проверяется задачей с известными условиями правильного ответа. Банк содержит проверенные варианты, а не случайно сгенерированные вопросы. Варианты должны проверять одинаковые умения с близкой сложностью. Результат раскрываем по навыкам и сохраняем версии заданий, ответы и рубрику. Эксперты разбирают спорные случаи. Контроль утечек и обновление банка необходимы, но полную защиту от списывания не обещаем.

## Слайд 12. Анонимность и приглашения

### Текст на слайде

#### До согласия

Компания видит навыки и результаты без имени, фото и контактов. API и PDF также сохраняют анонимность.

#### После принятия

Контакты открываются пригласившей компании и её разрешённым пользователям. Сервер фиксирует согласие.

#### Журнал решений

Отправлено, просмотрено, принято или отклонено. Причина отказа видна адресату, если пользователь её указал.

#### Граница MVP

Демо FSP ID имеет явную пометку. Свободный текст и файлы проверяем на раскрытие личности. Отзыв доступа относится к развитию.

### Выступление

Предлагаем анонимный профиль до согласия кандидата: компания видит релевантные навыки и подтверждения, но не имя, фото и контакты. Это правило должно действовать в интерфейсе, API и PDF. Свободный текст и вложения тоже могут раскрывать личность, поэтому их требуется очищать для анонимного просмотра. Полную неидентифицируемость по уникальным достижениям обещать нельзя. После принятия сервер открывает контакты только конкретной компании. Журнал сохраняет статус и причину отказа, если её указали. Система не должна выводить мотив отказа автоматически.

## Слайд 13. Архитектура MVP

### Текст на слайде

Предлагаемый стек: React, FastAPI, PostgreSQL, Docker Compose

#### Веб-интерфейс и API

Два кабинета. API связывает матрицу, тесты, профили, требования вакансий и приглашения.

#### Данные и правила

Хранилище фиксирует версии матрицы, оценок и событий. Сервер проверяет роль, адресата и согласие перед выдачей контактов.

#### Адаптер ФСП

Единый контракт для демоисточника и будущей интеграции. Совместимость с OIDC/Keycloak после согласования доступа.

### Подпись на слайде

Первичный грейд вычисляет рубрика теста. Для базового сценария GPU не нужен.

### Выступление

Для первого MVP выбираем обычный веб-стек: React, FastAPI и PostgreSQL, запуск через Docker Compose. Это предложение по реализации, а не описание уже собранного сервиса. Все критичные правила находятся на сервере: подтверждение категории, формирование выдачи и разрешение доступа. Результаты тестов и приглашения сохраняют историю изменений. Адаптер ФСП отделяет демоисточник от будущей интеграции. Первичный грейд определяется рубрикой, поэтому основной сценарий не требует GPU и не зависит от доступности языковой модели.

### Основание

ТЗ и Q&A не фиксируют обязательный стек. Выбор стека — решение команды. Боевой контракт ФСП отсутствует.
