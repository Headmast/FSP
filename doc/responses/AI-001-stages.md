# AI-001 — результат

Добавлены matching/invitation/conversation к profile/need/result. Matching показывает конкретные совпадения и пробелы самоописания, подтверждённую категорию/дату свидетельства, неизвестное и несовпадение категории потребности. Invitation подготавливает редактируемый текст; работодатель отдельно выбирает свидетельства и отправляет через существующий защищённый маршрут. Conversation помогает обеим сторонам обсуждать условия и зачёт из неизменяемого snapshot до/после решения; отказ сохраняется отказом.

В карточке/предложениях есть контекстные ссылки; в помощнике — понятные списки своих потребностей, доступных профилей и своих предложений. Чужие/скрытые объекты и некорректные ID — 404, неверная роль — 403, отсутствие выбора — 400. Matching доступен также по прежнему принятому гранту; новое приглашение требует опубликованного профиля и совпадающей категории.

Provider получает отдельную allowlist: категории, канонические совпадения/пробелы, safe proof, числовую вилку/формат и известные ограничения. Контакты, имя кандидата, приватное описание/опыт, произвольные tasks/next_step/title, ID/вопросы/ответы/ключи не передаются. Приглашение может показать полные условия человеку в редакторе; это отдельные данные страницы, не provider context. Генерация не создаёт Invitation, не меняет грейд или решение. Общий лимит 10/час, отказ 503 и блокировка активного теста 409 сохранены.

[90 тестов и хеши](../qa/AI-001-results.json) — PASS (8.751 с); [реальный локальный браузер](../qa/AI-001-browser.json) — PASS: карточка → объяснение → редактор → ручной зачёт/отправка → подготовка кандидата → ручное принятие → подготовка работодателя. [Мобильный редактор](../qa/AI-001-invitation-mobile.png) проверен визуально, горизонтального overflow нет. Тесты фиксируют приватность контекста даже после принятия, владение обеих ролей, неизменяемые условия, публикацию, категорию, лимит/активный тест/отказ и отсутствие автоматических действий. Ошибки подготовки тестов и синтаксиса до PASS сохранены в evidence.

Повторение браузера только на изолированной .runtime/qa DB: migrate/collectstatic, `python scripts/prepare_assistant_browser_fixture.py`, runserver на порту worktree, `node scripts/check_assistant_stages.cjs http://127.0.0.1:8041`. Fixture содержит только новые синтетические аккаунты; подготовка отказывает production/неподходящей DB. Идеальные ответы создаются внутри Python только для этого функционального fixture; это не валидация грейда. Учетные данные остаются в ignored .runtime/qa, в evidence их нет.
