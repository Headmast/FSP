# PROD-002 · Серверный этап, задача продолжается

Реализован полный серверный путь короткого задания: предложение по принятому приглашению, заранее видимые критерии/шкала/порог/бюджет/срок, отдельное согласие, закрытый черновик и явная отправка, ручная оценка компании и адресный зачёт. Это результат одной компании по одной потребности; общий грейд и ранжирование не меняются. Снимок после отправки не редактируется; повтор не создаёт дубликат, stale draft/review отклоняется. Код ответа не выполняется.

[Контракт продукта](../architecture/gap-challenges.md). Web — `/challenges/`, детали и отправка из принятого предложения. Read API/CLI/MCP дают безопасные структурированные поля без задания/критериев как свободного текста, ответа и комментария. Контакты не открываются этим согласием. Непринятое/чужое/отозванное приглашение не допускает отправку задания.

Отдельный отзыв ответа не закрывает контакты предложения, но прекращает выдачу ответа компании. Он записывается до изменения БД в durable journal с ID и неизменным UUID задания; после restore исходный доступ закрывается повторно, другая строка с переиспользованным числовым ID не затрагивается. Контактный отзыв закрывает и ответ. Очистка/удаление профиля стирает связанные тексты, критерии/ответ/оценку/зачёт и отвязывает кандидата, включая ORM cascade. Архив удаляется через 180 дней. Privacy format 2 блокирует downgrade на код, не очищающий эту модель.

**204 теста приложения** (21 новых challenge и один ledger type test), **15 клиентских**, **23 инструментальных** — PASS. **666 реальных HTTP случаев**, **76 paths / 122 operations**, 127 примеров и четыре контрпроверки — PASS. Native CLI/macOS keychain и modern/legacy MCP по реальному HTTP прошли для обеих ролей, по 12 чтений каждой. **Пять проверок настоящей SQLite**: одновременная отправка/оценка, гонка оценки с отзывом, реальное восстановление до отдельного отзыва и до очистки, retention/WAL/удаление canary — PASS. Старый privacy restore и upgrade старой схемы также проходят.

[Evidence этапа](../qa/PROD-002-stage.json), [HTTP](../qa/PROD-002-http-stage.json), [SQLite](../qa/PROD-002-storage-stage.json). Исправлены согласие/redirect общего кабинета, nonce привязки восстановления, отсутствие блокировки отзыва устаревшей revision и приватность owner/company результата после отзыва. Ошибки harness (пример тела и actor key) исправлены и отражены в evidence; не названы продуктовым дефектом.

Для **DONE ещё нужны** clean clone с настоящим браузером обеих ролей, визуальные desktop/mobile/errors, интеграция, публикация и HTTPS приёмка на собственных synthetic fixtures, версия privacy floor 2 на сервере. Эти проверки **NOT_RUN** на этом этапе. **17/27 DONE, 10 открыты**, PROD-002 IN_PROGRESS; основной опубликованный выпуск 11399cc не изменён. Linux native keyring/полный MCLI-013, реальный диктор и пилот не закрываются этой работой.

При ручном ревью нового формата журнала добавлена проверка типа записи до чтения полей: не-object JSON (список/null/строка/число/bool) теперь даёт fail-closed503; это подтверждено отдельным новым тестом реального API.
