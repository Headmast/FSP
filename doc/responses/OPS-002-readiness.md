# OPS-002 — исправлено

Дата 2026-10-11; mvp/implementation; база 0982d51.

/health проверяет чтение шести основных таблиц и возвращает общий 503 при ошибке БД без подробностей. Watchdog требует совпадения SHA, health=ok и отрисованной формы входа снаружи/локально. Ошибка локальной БД/шаблона даёт unavailable и обнуляет счётчик туннеля, не запускает лишние рестарты. Недоступный процесс приложения восстанавливается; публичный сбой при локальном health проходит прежние три тика.

23 проверки инструментов (включая настоящий локальный HTTP сервер) и 8 accounts тестов: PASS. Изолированная SQLite без таблиц: version=200, health=503. [Evidence](../qa/OPS-002-results.json), [пустая БД](../qa/OPS-002-empty-database.json). Повтор FTPS и сохранность при смене адреса покрыты регрессиями. Reboot остаётся OPS-003/NOT_RUN.

Для серверного применения нужны выпуск этого кода приложения и установка watchdog того же проверенного коммита: новый probe требует маркер формы. Они выполняются последовательно на контрольной точке; локальное выполнение не выдаётся за серверный деплой.
