# Cron: восстановление демо и постоянная страница

Постоянная точка входа: https://llmlove.ru/dreamwork/fsp-demo.html. Страница получает актуальный адрес из соседнего fsp-demo-status.json, обновляется раз в минуту и показывает время проверки в Москве. Данные старше трёх минут не выдаются за подтверждённую доступность; кнопки перехода отключены.

## Утилита

`scripts/maintain_demo.py` запускается пользовательским cron на digitarium каждую минуту. Проверяет /version/ снаружи и на localhost, сравнивает SHA с текущим release, требует /health/ с доступными основными таблицами и отрисованную форму /accounts/login/. При локальном отказе БД/шаблона показывает недоступность, не заменяя исправный туннель и не перезапуская доступный процесс. Истёкший процесс Pinggy запускается заново; для живого процесса требуются три последовательных неудачи внешней проверки. При смене адреса обновляет точные ALLOWED_HOSTS / CSRF_TRUSTED_ORIGINS и перезапускает только собственный Gunicorn. Секрет Django, база и текущая версия кода сохраняются. Миграции, наполнение данными и установка зависимостей при каждом тике не выполняются.

Проверка PID включает команду, целевой порт и каталог releases для приложения. Чужой PID не останавливается. Lock shared/maintenance.lock предотвращает параллельные тики и гонку с scripts/deploy_mvp_remote.py. Неудачная публикация статуса повторяется на следующем тике и сама по себе не перезапускает здоровое приложение.

## Установка

Коммитить исходники перед установкой. `python3 scripts/install_watchdog.py` отправляет **закоммиченные** maintain_demo.py и fsp-demo.html в ~/fsp-mvp/shared/tools, записывает SHA инструмента в watchdog-code.json и добавляет один блок FSP DEMO WATCHDOG в пользовательский crontab. Остальные задачи сохраняются; повторная установка не добавляет дубликатов.

Публикация на LLM Love — FTPS с защищённым каналом данных, повторным использованием TLS сессии и проверкой сертификата, ранее сохранённого FileZilla. Конфигурация shared/portal-publisher.json имеет права 0600 и находится вне Git. Поля: host, port, user, password, certificate_der (base64 DER), remote_directory. Пароль не указывать в cron строке или аргументах shell. Текущий каталог публикации /www/llmlove.ru/dreamwork. Утилита разрешает запись только двух имён: fsp-demo.html и fsp-demo-status.json.

HTML публикуется один раз при установке, JSON — на каждом тике через временный файл, проверку обратного чтения и rename. В статусе только адрес, SHA, доступность, метка mock и время; секретов и данных кандидатов нет. HTML содержит noindex/nofollow/nosnippet.

## Проверка и обслуживание

- Ручной тик: `/usr/bin/python3 ~/fsp-mvp/shared/tools/maintain_demo.py`.
- Расписание: `crontab -l`. Лог: ~/fsp-mvp/shared/logs/watchdog.log; процессные логи рядом.
- Состояние: shared/watchdog-state.json и shared/public-status.json.
- Обновить инструмент после нового коммита: scripts/install_watchdog.py. Опубликованная версия приложения при этом не меняется.
- Для удаления автоматизации удалить только блок BEGIN/END FSP DEMO WATCHDOG из crontab; не очищать весь crontab.

У бесплатного Pinggy меняется адрес примерно каждый час. Во время восстановления возможна пауза до следующего тика и запуска соединения. Постоянный адрес имеет страница LLM Love, а не сам туннель; после смены домена сессия пользователя демо требует нового входа. После reboot cron восстанавливает процессы, если системная служба cron активна и shared/current сохранены. Внешние сбои хостинга или провайдера могут задержать восстановление; страница отражает устаревший статус вместо ложного успеха.

Инструмент устанавливается заменой файлов через rename, чтобы cron не считал частично записанный Python файл. При старте приложения значения DEBUG, порта, БД, host/origin и секрета берутся из shared/.env; одноимённые глобальные переменные cron не переопределяют серверную конфигурацию.

OPS-002: [изменения и проверки](../responses/OPS-002-readiness.md). При обновлении сначала развернуть приложение с новой проверкой health/маркером login-form, затем установить соответствующий watchdog.

PROD-004: при первом тике UTC-дня watchdog вызывает `privacy_maintenance` через окружение и Python текущего релиза. После успеха записывает `privacy_sweep_day`; сбой не считается выполнением и повторяется следующим тиком. При публикации нового приложения устанавливать watchdog из того же принятого SHA: cron использует `shared/tools/maintain_demo.py`, а не автоматически обновляемый файл внутри current. [Политика хранения и защиты восстановления](../architecture/privacy-controls.md); проверки настоящего cron и прав файлов сохраняются в приёмке PROD-004. Это не доказательство настоящего reboot VPS.
