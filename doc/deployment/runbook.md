# Публикация и восстановление демо

Демо использует SSH alias digitarium и временный HTTPS туннель. Прототип фактически использует localhost.run: Cloudflare испытания не прошли. Секреты берутся из локальной SSH конфигурации и окружения сервера, не из документов репозитория.

## Ограничения окружения

Предыдущая инспекция: Debian 13, Python 3.13.5, около 1 ГБ RAM; git доступен, Docker отсутствует, nginx работает, passwordless sudo отсутствует. Повторить проверку перед публикацией. Не менять существующий nginx и другие приложения.

## Прототип

Развернуть точный коммит в отдельном каталоге. Запустить python3 -m http.server 8010 --bind 127.0.0.1 --directory prototype пользовательским процессом, сохраняющимся после выхода из SSH. Публикацию выполняет scripts/deploy_prototype.py; localhost.run подключается через отдельный SSH процесс без предоставления пользовательских ключей. PID и логи держать вне Git. Проверить внешний URL, полный сценарий и отключение SSH.

## MVP

Структура сервера: ~/fsp-mvp/releases/<SHA>, ~/fsp-mvp/shared/ и current как указатель на выбранную версию. В shared находятся .env, SQLite и логи. Gunicorn слушает 127.0.0.1:8011; отдельный tunnel публикует MVP. Прототип сохраняется отдельно.

До запуска: установить зафиксированные зависимости, проверить конфигурацию, резервировать базу корректным SQLite backup, выполнить миграции и collectstatic. Разрешённые hosts и CSRF origins — точный текущий адрес, без wildcard. Cookies secure, DEBUG=False; выполнить Django deploy checks и разобраться с каждым предупреждением.

После запуска: /health, /version, основной сценарий, HTTPS, выключение SSH, сохранность после перезапуска. Записать SHA и URL. Не публиковать окружение, базу и логи.

## Откат

Перед обновлением сохранить код предыдущего релиза и резервную копию базы. При дефекте остановить новый процесс, вернуть current на предыдущий релиз и перезапустить. Если миграции несовместимы назад, восстановить сохранённую базу с фиксацией потери последующих demo данных. Проверить health и сценарий; не обещать сохранность записи после резервной копии.

## Туннель и Pages

Временные туннели имеют изменяющийся адрес. Cloudflare испытания не прошли; детали в [P0](../qa/prototype-results.md). Рабочий резервный провайдер localhost.run также не даёт постоянного адреса. После остановки сервера потребуется ручное восстановление: автоматический запуск user services не подтверждён. Не объявлять это постоянным хостингом.

Существующий лендинг пока остаётся в корне. _config.yml исключает документацию и инструменты из стандартной Jekyll сборки, но это не контроль доступа и не проверка настроек Pages. Если Pages работает без Jekyll, переключить на сборку с явным набором файлов сайта до публикации. При переносе лендинга в static-site/ публиковать только этот каталог.
