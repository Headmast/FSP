# QA-001 — результат синтетической валидации

**Кратко:** зафиксированный набор проходит заранее заданные критерии на якорях и holdout; пограничные профили нестабильны. Это не доказательство валидности на людях. Банк ios-swift-1 оставлен без изменения.

Всего 320 измерений scoring и 4 oracle-проверки. Для каждого измерения отдельная копия профиля/Attempt на временной SQLite; production DB не используется. Строки и матрицы опубликованы целиком. Семантический oracle на каждом варианте — 8/8, расхождений ключа 0. Эталонные ответы выбираются по заранее заданным текстам/темам, а не по приватному correct; correct читается только для согласованной перестановки серверного ключа. [Контрфактический опыт](validation-counterfactual.json): намеренно испорченный ключ даёт FAIL, oracle mismatch=1. Так проверено, что validator не подгоняет ожидаемые ответы под ключ.

## Ошибки и различимость

Якорная матрица: без подтверждения 32/32, Junior 32/32, Middle 31/32; один Middle ошибочно получает аналитическую метку Junior на B/повторе. Это anchor-Middle-2: пробел Sendable плюс заданный провал внимания на protocol вопросе оставляют Swift без верных ответов. В A отсутствие COW и провал внимания совпадают в одной позиции, Hashable остаётся верным. Правило области отвергает B. Ошибка не удалена из набора.

На якорях средние Junior-тест баллы для эталонных unconfirmed/Junior/Middle: 3.4375 / 7.1875 / 7.5. Middle-тест: 0.6875 / 2.40625 / 6.84375. Доли успешного Middle: 0 / 0 / 0.96875. На holdout матрица 16/16 в каждой группе. Это разделение искусственных знаний, не оценка числа опытных кандидатов на рынке.

Пограничные четыре профиля: test–retest 0.25, A/B 0.75. Смена одного ответа у порога существенно меняет решение. Порог не смягчался, эти случаи не скрыты и не получили удобную «правильную» метку. Их данные были заранее выделены как challenge-набор. Для ответственного применения нужны более длинный/практический тест и QA-002 на людях.
