# PROD-002 · Короткое задание по конкретному пробелу

Статус: DONE. [Приёмка](../qa/PROD-002-complete.json), релиз fd2d1ee; контракт продукта и ограничения ниже подтверждены local/browser/live проверками.

Компания отправляет задание из **принятого собственного предложения**. Это сохраняет прежний порядок контактов: задание не служит обходом принятия предложения. Навык должен входить в её потребность; отсутствие в самоописании отмечается как пробел самоописания, присутствующий навык — как отдельно не проверенный. Это не автоматическое доказательство дефицита.

До согласия кандидат видит задачу/инструкцию, навык и основание, 1–5 критериев, баллы 0/1/2, порог, срок и бюджет 5–60 минут. После отдельного согласия сервер фиксирует начало; срок отправки — минимум общего deadline и начала плюс бюджет. Черновик сохраняется до срока и не виден компании. Явная отправка передаёт ответ только ей. Текст/код не выполняется и не оценивается AI.

Ручная оценка компании содержит баллы по каждому неизменному критерию и объяснение. Достаточность определяется объявленным порогом; пользователь видит, что это оценка данной компании, а не свидетельство ФСП/профессионального грейда. Явный зачёт достаточного результата относится только к данной потребности; не меняет category, test_score, 85/10/5 ranking или историю экзамена.

| Состояние | Действие | Результат |
| --- | --- | --- |
| offered | кандидат согласен / отказ; компания отзывает ещё не начатое | accepted / declined / withdrawn |
| accepted до срока | кандидат сохраняет черновик / отправляет | accepted / submitted |
| submitted | компания оценивает по объявленной шкале | reviewed |
| reviewed, достаточный результат | компания явно зачтёт | credited_at, статус reviewed |
| accepted/submitted/reviewed | кандидат отзывает доступ к ответу | revoked; контакты предложения не меняются |
| offered/accepted после срока | новые действия блокируются | эффективный expired без записи от GET |
| любой | privacy контактный отзыв / очистка | revoked / erased; старый grant не оживляет ответ |

Снимок задания после отправки не редактируется. Один навык на одно предложение — одно задание; повтор не создаёт дубликат. Revision защищает draft/submit/review от stale записи; повтор того же принятого действия не продлевает таймер и не меняет результат. Отозванное задание не открывается новым контактом компании. Отказ по заданию не меняет accepted приглашения.

Кандидат видит свои данные; компания получает ответ только после отправки и при действующем согласии задания **и** исходного принятого предложения. Другие компании не получают даже результат через публичный профиль/рейтинг. Read API/CLI/MCP содержит только безопасные структурированные поля; инструкции, ответ и комментарий доступны в собственном веб-кабинете. Новые записи в MVP подтверждаются браузером с CSRF.

Privacy version повышается до 2: код версии 1 не очищает новую модель и потому не допускается для downgrade. Контактный отзыв прекращает выдачу компании, собственная история кандидата сохраняется до очистки; очистка стирает свободные тексты, критерии/ответ/оценку/зачёт и отвязывает кандидата. Сокращённая история компании имеет 180-дневный срок; journal/floor и restore fence сохраняются. Новая модель не даёт права отозвать уже скачанные копии.

Отдельный отзыв ответа тоже записывается в durable journal до изменения БД: `revoke_challenge`, ID и неизменный UUID задания, без содержимого. После restore запись закрывает исходное задание и не затрагивает другую строку с повторно использованным числовым ID. Чужая компания не видит сохранённый ответ/баллы после отзыва; кандидат хранит собственную историю до очистки. Отзыв применяется даже при устаревшей revision, поэтому одновременная оценка компании не может помешать владельцу закрыть доступ.
