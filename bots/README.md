# Информационный бот «Трудяжки» для Telegram и MAX

Самостоятельный бот на моках для соискателя. Общий сценарий и два имитированных транспорта: Telegram и MAX. Демо переписки работает в браузере; те же команды можно выполнять в терминале. Ни токены, ни backend, ни сетевой AI не нужны. Всё выполняется на вымышленных данных.

## Запуск

Из корня checkout:

```sh
python3 -m http.server 8067 --bind 127.0.0.1 --directory bots
```

Открыть [демо](http://127.0.0.1:8067/). Браузеру нужен HTTP-сервер для ES-модулей; открытие index.html через file:// не поддерживается.

Терминал (Node.js 20+):

```sh
node bots/cli.mjs telegram
node bots/cli.mjs max
```

В CLI кнопки вызываются как `!accept:o1`, `!confirm:o1`. `/event` добавляет новое моковое приглашение, `/exit` завершает процесс. Состояние CLI существует до выхода.

## Что умеет бот

| Команда | Результат |
|---|---|
| `/start`, `/menu` | Приветствие и разделы |
| `/profile` | Профиль, категория Junior, результат демо-теста, источник достижений |
| `/status` | Следующий шаг кандидата |
| `/offers` | Приглашения: компания, задачи, зарплата, формат, статус |
| `/prepare` | Памятка к первому разговору |
| `/help`, `/faq` | Частые вопросы и поиск по словам |
| `/settings` | Уведомления выбранного канала |
| `/privacy` | Правила открытия контактов |

Можно писать «Кто видит мои контакты?», «Как пройти тест?», «Где зарплата?». Ответы детерминированы, свободного генеративного AI нет. При неизвестном запросе бот предлагает меню.

Принятие приглашения требует отдельной кнопки «Подтверждаю: открыть контакт». До этого контакты закрыты; после принятия вымышленный контакт доступен только конкретной компании. Отказ позволяет указать причину или пропустить её. Повторное действие не создаёт повторного согласия или события.

Переключите Telegram/MAX: профиль и решения общие, переписки и настройки уведомлений свои. «Новое приглашение» создаёт единственный мок события и доставляет его только в каналы с включёнными уведомлениями. При отключении событие всё равно видно в списке приглашений.

## Данные и границы

- Браузер хранит состояние в `localStorage`, ключ `fsp-candidate-bots-v1`. Сброс удаляет только состояние бота, остальные приложения не затрагивает. Если storage недоступен, бот работает в памяти вкладки. Повреждённый снимок заменяется fixtures.
- Профиль заранее задан; реальной авторизации и привязки мессенджера к аккаунту нет. Предпочтения между вкладками не синхронизируются автоматически.
- Приём приглашений и раскрытие вымышленного контакта происходят только внутри этого демо, не меняют Django и основной прототип.
- Тест проходится на платформе; этот информационный бот объясняет правила и показывает моковый результат, не проверяет ответы и не присваивает категорию.
- Реальные Telegram Bot API / MAX API, webhooks, polling, доставка уведомлений, фоновые напоминания и интеграция с профилем платформы не подключены. Объекты из transports.mjs — внутренний формат демо, не официальный протокол мессенджеров.

## Структура и проверка

`engine.mjs` — данные и сценарии, `transports.mjs` — моковые каналы, `app.mjs` — браузерная оболочка, `cli.mjs` — терминальная оболочка. Внешних зависимостей для запуска нет.

```sh
node --test scripts/check_candidate_bots.mjs
node scripts/check_candidate_bots_browser.cjs
python3 scripts/check_docs.py
git diff --check
```

Браузерная проверка требует Playwright и запущенный сервер 8067. При наличии пакета в другом каталоге задайте `NODE_PATH` для своей среды. Скрипт сохраняет скриншоты и JSON в doc/qa/.
